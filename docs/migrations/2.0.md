# Upgrading to Sigenergy 2.0

## Before installing the beta

Version 2.0 changes the stored states of eight status sensors from English labels to stable enum keys. Automations, templates, dashboards with explicit state comparisons and API consumers must use the new keys. The included English display labels can still look exactly like the old states.

Keep your existing entity IDs. No integration recreation is needed. User-defined names, device links, energy counters and historical records must be retained. Old historical status strings are not rewritten.

Only the eight sensor states listed below change. Remote EMS **select** options and write commands do not change. Do not replace strings in select.select_option calls based on this sensor migration table. Alarm text, general entity names and broader localization are outside this beta.

## Automation and template examples

Use your existing entity IDs; these are examples:

```jinja2
{# Before #}
{{ is_state('sensor.sigen_inverter_running_state', 'Running') }}

{# 2.0 #}
{{ is_state('sensor.sigen_inverter_running_state', 'running') }}
```

For the **EMS Work Mode sensor**, compare `max_self_consumption` instead of `Maximum Self Consumption`. For a charger's running-state sensor, compare `charging` instead of `Charging`.

Update references deliberately; this integration does not rewrite your automations.

## Unknown values and availability

An unrecognized raw register value now produces Home Assistant `unknown` rather than an `Unknown: ...` string when the sensor is otherwise available. Missing source data also has no sensor reading. A real communication/availability failure is still Home Assistant `unavailable`.

DC charger raw status 7 is a valid reported device status: its stored key is `charger_unavailable` and its English label is Unavailable. It does not by itself mean the Home Assistant entity is unavailable. Templates that previously compared the capitalized `Unavailable` device status must use `charger_unavailable`.

## Installation checks

Requirements remain Home Assistant Core 2026.10.0+ and Python 3.14.2+. After an approved installation, restart Home Assistant completely. Check the integration version, the affected automations, sensor options/labels, entity IDs and energy counters. Test unusual device states offline rather than provoking a physical fault or grid outage.

For rollback, reinstall the previously tested beta and restart HA. Automation comparisons adapted to 2.0 must also be restored to their previous form. Historical rows from each version retain the state strings recorded by that version.

This guide prepares a beta; it does not authorize installation, merging or release publication.
