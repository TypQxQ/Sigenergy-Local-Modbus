# Sigenergy ESS 1.3.0

This release moves Sigenergy communication to Home Assistant's shared Modbus connection broker and brings the startup, recovery and energy-counter work tested through the 1.3.0 betas.

## Requirements and upgrade

- Home Assistant Core 2026.10.0 or newer, with Python 3.14.2 or newer.
- Upgrade through HACS and restart Home Assistant completely to load the Python modules.
- Existing configuration, entity IDs, device links, history and user-disabled entities are retained. Recreating the integration is not required.
- Manual installation: extract the release's `sigen.zip` directly into `custom_components/sigen/`; the files are at the ZIP root.
- For older Home Assistant installations, stay on 1.2.7.5 until Home Assistant has been upgraded.

## Communication and startup

- Use HA's shared Modbus connection management and batched register reads.
- Persist capabilities per endpoint/device, validate identity and firmware, and discover optional registers incrementally instead of blocking every restart on a full probe.
- Narrow timed-out or incomplete discovery blocks over later intervals so a silent optional address cannot hide healthy neighbours. Retain retry backoff, keep connection failures as whole-block retries, and never treat a timeout as proof that a register is unsupported.
- Preserve completed reads during interrupted polls, drain surviving requests before replacement work, and protect in-flight transactions from caller cancellation.
- Keep healthy readings available when supported register blocks fail. Both diagnostic downloads now expose partial-read counters, affected fields, block addresses and recovery information.
- Restore entities discovered in the background and handle integration reloads without losing registry entries or diagnostic availability.

## Energy counters and alarms

- Restore PV integrators from validated native snapshots and Recorder history, preserving kWh precision and display-unit overrides. Existing counters with unverifiable data stay unknown and retry instead of publishing a false zero.
- Resume restoration when a pending Recorder query completes; expose restore sources, exact startup values, queue/query phases and failure details in diagnostics.
- Fix PV-string energy undercount when identical power values are reported repeatedly. Event intervals use `last_updated`, including attribute-only events, while timer checkpoints retain their existing accounting. No historical statistics or accumulated baselines are rewritten. Thanks @lnafziger for identifying the issue and contributing the initial fix and regression tests (#452, #453).
- Report Alarm 7 bitmap `0xFFFF` as `Unknown Alarm`, keeping normal availability and the raw value in diagnostics. Documented Alarm 7 values and other alarm bitmaps keep their existing meanings.

## Remote EMS

Changing the plant Remote EMS enable switch or mode now waits for a new, matching device readback after the write. Cached matching values are not accepted as confirmation. A confirmation failure reports an error and does not automatically replay the write; check the actual device state before deciding to send another command.

## Remaining investigations

- #427: the original report of several control entities becoming unavailable together still needs confirmation from the reporter. The readback improvements address the enable/select timing path but do not recover calls that Home Assistant rejects before they reach the integration.
- #450: intermittent AC-charger register timeouts were reported during beta testing. Full logs and diagnostics are still needed to establish the cause. This release exposes those partial failures; it does not claim to resolve that report.

The enum/state-key feature from #448 is deferred to a later version.

## Validation

The integrated fixes pass all 261 regression tests with both supported Modbus versions, 4.12.3 and 4.12.4. New coverage exercises repeated reports, attribute-only events, timer/event transitions, first events after restoration, silent-address discovery, incomplete responses and persisted fallback jobs. The remaining suite covers startup, capability caching, cancellation, recovery, Remote EMS readback, PV restore and diagnostic downloads.

B8 was also verified after restarts on our two installations; that check confirmed restored counters, unchanged units/statistics and the Alarm 7 presentation. The new PV interval correction has deterministic regression coverage; it has not been physically measured against a live production reference.

Thank you @bencope for the shared-Modbus migration and everyone who supplied beta diagnostics and test results.
