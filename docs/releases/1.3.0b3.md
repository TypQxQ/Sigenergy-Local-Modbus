# v1.3.0 Beta 3 - Startup timeout and timing diagnostics

This beta addresses initialization failures when slow Modbus communication
uses most of the first refresh's time budget before inverter and charger
discovery can complete, as reported in [#436](https://github.com/TypQxQ/Sigenergy-Local-Modbus/issues/436).

## Changes since Beta 2

- Allow 180 seconds for the first successful data fetch. Subsequent updates
  retain the 60-second deadline, including after a runtime failure.
- Save register-support results after every completed bulk-probe block.
  An interrupted probe can resume with the remaining unknown fields in the
  same device instance. This is not a persistent cache across HA restarts
  or a new hub created after a failed setup.
- Measure durations with a monotonic clock and include failed/cancelled
  attempts in timing diagnostics.
- Add startup duration, timeout/failure counters, and per-device durations
  to integration and device diagnostics. Debug logs include a
  `Sigenergy update timing:` summary for each attempt.

Existing protection for in-flight Modbus transactions and fresh Remote EMS
write readback is retained. Device durations include shared-connection
waiting and can overlap. The workflow deadline does not forcibly terminate
an already-sent wire transaction.

## Checking timings

After installing the beta, restart Home Assistant completely. Go to
**Settings -> Devices & services -> Sigenergy ESS**, open the integration's
menu, and select **Download diagnostics**. In `data.coordinator`, inspect:

- `startup_fetch_time`: first successful fetch duration in seconds.
- `latest_fetch_time` and `largest_update_interval`: latest and longest
  attempt durations since the integration was initialized.
- `update_timeout_count` and `update_failure_count`.
- `latest_update_timing`: phase, status, deadline, fetch/cleanup/total times,
  and plant/inverter/charger workflow durations.

One local HA 2026.10.1 installation completed startup in **2.325 seconds**.
Three subsequent fetches took **0.136-0.207 seconds**, polling every five
seconds, with no recorded update failures or timeouts at the time of the
check. These are reference measurements, not performance guarantees or a
long-duration reliability test.

## Requirements and feedback

**Home Assistant Core 2026.10.0+ and Python 3.14.2+ are required.**

In HACS, enable beta versions and select **1.3.0b3**. Restart Home Assistant
after installation. If initialization still fails or polling is slow, attach
the diagnostics and a complete debug log covering the attempt to
[#436](https://github.com/TypQxQ/Sigenergy-Local-Modbus/issues/436).
