# v1.3.0 Beta 5 - Restore entities and PV energy safely

Beta 4 could keep polling successfully while entities discovered after startup
remained unavailable. It could also fail to unload after discovery completed,
leaving diagnostics requests returning HTTP 500. This beta fixes both entity
lifecycle regressions reported in issue #436.

It also protects calculated PV energy counters against restarting from a stale
Home Assistant restore snapshot when newer values already exist in Recorder.

## Changes since Beta 4

- Schedule `EntityPlatform.async_add_entities` through the config entry's task
  API when background discovery confirms support. This platform method is a
  coroutine, unlike the synchronous add-entities callback used during setup.
- Remove each discovery listener only once, whether discovery finishes first
  or the integration unloads first. Ignore queued notifications after unload.
- Correct the test doubles to match Home Assistant's asynchronous platform
  method and non-idempotent coordinator listener removal. Cover restoration
  without duplicate tasks, unload after discovery and queued notifications
  after unload.
- Preserve existing entity IDs, device links and user-disabled flags.
- Reconcile PV integrators with the newest valid pre-start Recorder value and
  restore snapshot, using their timestamps and original energy units. Prefer
  native precision when timestamps match. Explicit manual initialization retains
  priority; historical peaks are never used as an automatic correction.
- Restore same-day PV energy, but start a new daily period after midnight in
  Home Assistant's timezone. Schedule the daily reset at local midnight, including
  daylight-saving transitions. Lifetime counters are not reset.
- Keep existing counters unknown if Recorder is temporarily unavailable or no
  valid restoration data can be established. Retry after 60 seconds; a slow query
  gets a 10-second initial wait and is reused instead of stacking database reads.
  A genuinely new registry counter can start at zero.
- Start integration only after restoration succeeds. Do not estimate production
  across downtime or let an older queued power event reduce the counter. Normal
  polls do not query Recorder.

## Installation and checking

Restart Home Assistant completely after installing Beta 5 to load the corrected
Python code. An integration reload alone does not reload these modules.

With a fresh support cache, optional entities should gain live values gradually
as background discovery confirms their registers. Normal polls continue during
discovery. With a populated cache, known-supported registers are read at startup.
An integration reload after discovery should complete without requiring a restart,
and integration diagnostics should remain available.

## Verification

- All 202 local regression tests passed on Python 3.14 with
  `modbus-connection==4.12.3` and `4.12.4`.
- PV restore tests reproduce the observed stale snapshot (12.471733 kWh) and
  newer Recorder value (12.500856 kWh). They also cover historical Wh/kWh/MWh
  units, native precision, midnight/DST, manual reset, new versus existing
  counters, Recorder failures, late queries, retry and unload.
- On Home Assistant 2026.10.1, a fresh-cache dev test restored all 89 previously
  valued entities from an initial 22, with zero update failures or timeouts.
  A second Home Assistant client remained connected to the same Sigenergy during
  this test. All 398 existing entity IDs, device links and disabled flags were
  preserved.
- A further runtime test removed one supported field from the dev cache, confirmed
  its entities returned through background discovery, and then successfully
  reloaded the integration with diagnostics still available and no Sigenergy
  errors. Registry identities and user-disabled flags remained unchanged.
- The Recorder reconciliation was checked through a complete HA restart and an
  integration reload on the dev installation. All 27 numeric energy sensors
  retained their units, with no decreases in cumulative counters. All six PV
  string energy values matched before/after, including MWh display overrides.
  The reload completed in 0.359 s, all 398 registry identities/user flags remained
  unchanged, and sampled polls reported zero failures/timeouts. This live check
  ran after solar production had stopped; the stale-snapshot regression is
  reproduced separately in automated tests. Historical statistics were not edited.

The capability cache, discovery pacing, polling deadlines and frequency of static
metadata reads retain their Beta 4 behavior. This fixes entity handling; it does
not establish the cause of slow Modbus communication in other installations.

**Home Assistant Core 2026.10.0+ and Python 3.14.2+ are required.**
