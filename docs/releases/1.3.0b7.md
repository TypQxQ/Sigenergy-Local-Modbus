# v1.3.0 Beta 7 - Correct PV restore selection explanation

## Changes since Beta 6

- Correct the DEBUG explanation when a PV restore snapshot and Recorder sample
  have the same timestamp. The reason now reads `snapshot preferred at equal
  timestamp`. A snapshot can use the stored display state if native restore data
  is missing or invalid, so the explanation must not imply native precision in
  every case.
- Clarify the helper's documentation to describe snapshot preference on a tie.
- Add regression coverage for missing and invalid native restore data, alongside
  the existing test that verifies full native precision when it is available.

Counter selection, energy values, unit conversion, retry timing and Modbus
polling are unchanged. Historical energy statistics are not modified.

## Verification

- All 212 regression tests passed on Python 3.14.7 with
  `modbus-connection==4.12.4`.
- The PV restoration suite covers both stored-state fallback cases and exact
  native values at equal timestamps, together with restart, retry and midnight
  behavior.

Restart Home Assistant completely after installing Beta 7 to load the updated
Python modules. An integration reload alone does not reload their code.

**Home Assistant Core 2026.10.0+ and Python 3.14.2+ are required.**
