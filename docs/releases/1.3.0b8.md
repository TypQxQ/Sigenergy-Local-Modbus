# v1.3.0 Beta 8 - Unknown Alarm 7 bitmap handling

Some devices answer register 30281 (Merged Alarm 7) with `65535` (`0xFFFF`),
setting all bits, including the bits not defined by Appendix 13. Beta 7 decoded
this as `OVGR fault, RPR fault`.

Beta 8 reports this specific Alarm 7 value as `Unknown Alarm`. The existing
entity keeps its normal availability and reports `alarm_status: unknown`,
`alarm_reason: all_bits_set` and the raw value in its attributes. Both
integration and device diagnostics explain it under `unknown_alarm_values`.
The original raw coordinator value remains available for troubleshooting.

The register stays in normal polling and the same entity returns to the
documented alarm text on a known bitmap. Discovery keeps its successful read
result. The meaning of the all-bits-set value is uncertain; it does not prove
that the register is unsupported or that either named fault is active.

Alarm 7 values `0`, `1`, `2` and `3` retain their meanings: no problem, OVGR,
RPR and both faults. The rule does not apply to other alarm registers, where
all sixteen bits can have defined meanings. This is a targeted firmware
compatibility rule, not a general sentinel rule from the protocol document.

Entity IDs, device links, history, energy counter restoration and polling
intervals are unchanged. No Modbus writes or history changes are introduced.

All 245 regression tests passed on Python 3.14.7 with both supported
`modbus-connection` versions, 4.12.3 and 4.12.4.

Regression coverage exercises the sensor value and availability paths, all four
documented Alarm 7 bitmaps, missing data, recovery on the next poll, other alarm
registers, both diagnostic downloads and real Modbus field decoding.

Restart Home Assistant completely after installing Beta 8 to load the changed
Python modules.

**Home Assistant Core 2026.10.0+ and Python 3.14.2+ are required.**
