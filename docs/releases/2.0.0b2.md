# Sigenergy ESS 2.0.0b2

- Plant power-limit controls (ESS charging/discharging, PV, grid import/export
  and PCS import/export) report `unknown` for all-ones `0xFFFFFFFF` readback,
  instead of displaying 4,294,967.295 kW. The controls remain writable; valid
  zero values and actual read failures keep their existing behavior.
- Improve #427: a read interrupted by a control write can restart once within
  the existing update deadline, after protected writes on that connection finish.
  The interrupted samples are discarded; commands are never replayed. Identity
  changes and real communication failures retain their existing error handling.
- Fix #466: missing control readings no longer appear as confirmed `0`/`off`
  or a default select option. Affected readable controls become unavailable
  until their readings recover; healthy readings survive partial failures.
  A failed poll with no usable readings reports an update failure, while
  pending discovery remains supported. Write-only command behavior is retained.
- Fix #467: inverter power-factor adjustment readback is scaled once, matching
  the requested setting (for example, `0.95` stays `0.95`).
- Fix #468: inverter power factor register 31023 is decoded as signed S16,
  preserving negative values such as `-0.95`.
- New **Battery time remaining** plant sensor, with English and Swedish names.
  Estimates battery-only autonomy above backup reserve at current household
  consumption, including during charging or idle. Uses hours and existing
  coordinator data without additional Modbus requests. Missing inputs or no
  consumption above reserve give `unknown`; reaching reserve gives `0`.
- Shorter README with installation, setup and troubleshooting in one place.
- Compact logo and status badges, plus step-by-step Modbus TCP activation in
  the Sigenergy app.
- Battery-time dashboard template avoids division by zero when battery power
  is zero or unavailable.
- Installation instructions for the built-in Marketplace in Home Assistant
  2026.11+, with HACS instructions retained for 2026.10.
- Device layout, Modbus limitations and Remote EMS sequencing moved to the
  [usage guide](https://github.com/TypQxQ/Sigenergy-Local-Modbus/blob/v.2.0.0b2/docs/USAGE.md).

Existing helpers are retained; update dashboard references and convert hours to
minutes where needed. The read fixes do not replay commands or change
energy-counter calculations. Requirements remain Home Assistant Core 2026.10.0+
and Python 3.14.2+.

The register datatype correction triggers a one-time refresh of the inverter's
cached register support map. Some inverter sensors can be temporarily unavailable
while incremental discovery completes. On DEV this took about three minutes;
existing entity IDs and accumulated energy counters were retained.

Upgrading from 1.x? Eight status sensors now store stable keys instead of English
labels. Read the [2.0 migration guide](https://github.com/TypQxQ/Sigenergy-Local-Modbus/blob/v.2.0.0b2/docs/migrations/2.0.md)
before updating automation comparisons. Entity IDs, custom names, energy counters
and existing history are retained.
