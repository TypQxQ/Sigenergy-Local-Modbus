# Sigenergy ESS 2.0.0b4

- Document separate confirmed-alarm and uncertainty/offline indicators in the
  [usage guide](https://github.com/TypQxQ/Sigenergy-Local-Modbus/blob/v.2.0.0b4/docs/USAGE.md#alarm-monitoring).
  Alarm 7's ambiguous `0xFFFF` remains **Unknown Alarm** and is not classified as
  a confirmed fault or as unsupported.

- Reject duplicate inverter/AC charger addresses on the same host and port during
  setup and editing. Reusing an ID on another endpoint remains allowed. Errors
  are translated in all 11 languages; unchanged device settings save without
  removing or recreating entities.
- Make bundled Energy Flow gauge sensors unavailable when their required inputs
  are missing. Preserve valid zeroes and correct the battery power source and
  direction.
  Update your copied dashboard package manually to receive these example changes.
- Add Energy Dashboard energy/power mappings, focused Recorder exclusions, AC
  charger troubleshooting and model-specific firmware notes. SigenMate SPC101
  is documented as a read-only user report, not blanket write-control support.

- Limit explicit device removal to the selected integration identifier and its
  registry descendants. Similarly named neighbouring inverters and nameless
  unrelated devices are no longer selected by name prefix.
- Preserve device/entity registry entries during inverter or AC charger address
  changes, retaining IDs, custom names, areas and entity settings.
- Add optional **Configure → Power flow indicators** hysteresis, with translated
  settings in all 11 languages. Defaults when enabled are on above 50 W and off
  at or below 10 W. It is disabled by default; measured power, energy and polling
  are unchanged. Invalid readings clear the remembered state.
- Document 2.0 grid outage/recovery notifications using stored enum keys and
  distinguish off-grid status from communication loss. Explain the existing
  third-party PV total/daily sensors, enabling disabled sources and avoiding
  double counting.

- Fix AC charger output current being capped at 32 A (#479). Use the smaller of
  the charger's reported rated current and input-breaker rated current, including
  48 A models. Missing or invalid ratings make the control unavailable until
  valid readings return; unsafe requests are rejected before writing.

Includes all changes from 2.0.0b3. Requirements remain Home Assistant Core
2026.10.0+ and Python 3.14.2+.
