# Sigenergy ESS 2.0.4

**Before upgrading.** Requires Home Assistant Core 2026.10.0 or later. Restart Home Assistant after updating through HACS. This release includes the changes tested in 2.0.4 Betas 1–4. If you already run Beta 4, the integration code is unchanged apart from the version number.

- **Connection recovery.** After an eligible read timeout, the integration can reopen the shared connection and retry the block once. A second timeout stops reads on that endpoint for the current poll. If the poll reaches its deadline, readings that already arrived can still be kept. A write response timeout can also trigger connection recycling, subject to the reconnect cooldown. [#517](https://github.com/TypQxQ/Sigenergy-Local-Modbus/pull/517) · [#527](https://github.com/TypQxQ/Sigenergy-Local-Modbus/pull/527)
- **AC charger sensors.** After one failed AC charger read, affected sensors keep their last value for that poll. A second consecutive missed read makes those values unknown. Plant consumption uses the same held charger power, while charger controls still require a live reading. In a reported 24-hour Beta 4 test, the charger state never became unknown despite 53 lost charger replies. [#520](https://github.com/TypQxQ/Sigenergy-Local-Modbus/pull/520) · [test results](https://github.com/TypQxQ/Sigenergy-Local-Modbus/issues/450#issuecomment-7114276331)
- **Command handling.** Commands have ten seconds to acquire this integration's connection lock. Commands that expire or are cancelled while waiting locally are withdrawn. Once handed to the shared Modbus dependency, a write can still be delayed and may finish after its automation is cancelled. Failed writes are never automatically replayed. [#527](https://github.com/TypQxQ/Sigenergy-Local-Modbus/pull/527)
- **Write confirmation.** Ordinary write actions return after acknowledgement and schedule a background refresh; entity state can update afterwards. Remote EMS enable and mode changes still wait for fresh confirmation. Polling, discovery and writes share connection coordination, and unloading drains protected requests. [#527](https://github.com/TypQxQ/Sigenergy-Local-Modbus/pull/527)
- **Compatibility and diagnostics.** Setup and options forms support the dependencies used by Home Assistant Core 2026.10 and 2026.11. Diagnostics now include endpoint timeout and recovery counters, held charger fields, and recent command outcomes. Write errors have translated messages, including an explicit error in read-only mode. [#524](https://github.com/TypQxQ/Sigenergy-Local-Modbus/pull/524) · [#527](https://github.com/TypQxQ/Sigenergy-Local-Modbus/pull/527)

**Known limitations.** Intermittent Modbus timeouts reported in [#514](https://github.com/TypQxQ/Sigenergy-Local-Modbus/issues/514) also occur on Beta 4 and remain under investigation. This release improves recovery but does not establish or fix every cause. A missing charger reply can still pause plant and inverter reads for the twenty-second response timeout before recovery; retained charger values do not remove that gap. [#450](https://github.com/TypQxQ/Sigenergy-Local-Modbus/issues/450#issuecomment-7114276331)

If a write acknowledgement is lost, the device may already have applied the command. Read the current state and let your controller issue its current decision again.
