# Sigenergy ESS 2.0.4 Beta 4

Commands now have ten seconds to acquire this integration's endpoint lock. Expired or cancelled local commands are not sent later. After handoff to the shared Modbus dependency, connection setup and other consumers can still delay a write, and it may finish after its automation is cancelled. Such writes remain tracked and are never automatically replayed.

- Polls, discovery, probes and writes share endpoint serialization. A write response timeout can recycle an existing connection under the same cooldown as polling; a failed connect with no link does not consume that cooldown.
- Ordinary write actions return after acknowledgement and schedule a background refresh. Entity state can update afterwards.
- Remote EMS enable/mode actions retain fresh confirmation, share confirmation polls and cannot cancel another command's poll. Up to four EMS commands are admitted per config entry, and sixteen locally waiting writes per endpoint.
- Read-only writes fail explicitly. Diagnostics include command outcomes and bounded recent history. Error messages cover all supported interface languages.
- Unloading drains protected requests without cancelling them when the unload caller is cancelled.

Requires Home Assistant Core 2026.10.0 or later. Restart Home Assistant after updating through HACS. An uncertain acknowledgement does not establish whether the device applied a command: read current state and let the controller issue its current decision again. This beta does not claim to resolve every cause of the older #526 charging incident.
